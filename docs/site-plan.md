# 个人站点方案设计

> 状态：草案 v1，待确认第 6 节决策项
> 更新：2026-11-08

---

## 1. 定位

**一句话**：一个可信的个人技术档案 —— 让导师、同学、未来的面试官在 30 秒内知道「你是谁、在做什么、做得怎么样」。

用户画像决定了内容重心。计算机技术专硕研一，意味着：

- 你有**能拿得出手的代码**（项目），但没有多年工作经验做背书；
- 你有**正在积累的知识**（论文、课程、踩坑），这类内容新鲜、真实、别人搜得到；
- 你的时间**很贵**（课程 + 科研 + 实习准备），站点必须能低维护地活下去。

所以这个站不是「博客」，是**三件东西的组合**：

| 板块 | 回答的问题 | 谁在看 |
|---|---|---|
| 项目 | 你动手做过什么 | 面试官、导师 |
| 文章 | 你想清楚了什么 | 同行、未来的自己 |
| 关于 | 你是谁、怎么联系 | 所有人 |

### 明确不做的事

- ❌ 不做花哨的动效和入场动画（三个月后你自己都会嫌烦）
- ❌ 不做全站搜索、评论、标签云到第一版（那是第二阶段的事，90% 的个人站死在这一步之前）
- ❌ 不追求日更。**每月 2 篇有质量的长文 > 每周 1 篇水文**

### 2.3 导航取舍

第一版只放 **4 个入口**：文章、项目、笔记、关于。
「笔记」在第二阶段再上线；导航项少，是为了让每个入口都有内容撑着 —— 空板块比没有板块更伤。

## 3. 技术选型

### 3.1 结论

| 层 | 选择 | 理由 |
|---|---|---|
| 框架 | **Astro 7.x** | 内容优先，默认零 JS；博客场景的甜点区 |
| 内容 | Markdown（+ MDX 按需） | 纯文本，永不锁定，十年后还能读 |
| 内容校验 | Content Collections | frontmatter 类型安全，写错字段构建即报错 |
| 样式 | **原生 CSS + 设计变量** | 极简风格 CSS 量很小，见 3.3 |
| 部署 | GitHub Pages + Actions | 免费、与你要求一致 |
| 图床 | 仓库内 `src/assets/` | Astro 自动压缩，省事 |

### 3.2 为什么是 Astro（而不是 Next / Hugo / Hexo）

- **对 Next.js**：Next 是应用框架，你会为了一个博客写一堆 `page.tsx` + 客户端组件，还默认带 JS 运行时。Astro 是内容框架，天然干这件事。
- **对 Hugo**：Hugo 构建快，但 Go 模板语言对前端背景的人是负资产，改样式要跟模板系统搏斗。
- **对 Hexo**：生态在衰退，插件质量参差，主题定制常常要改别人的源码。
- **对 Astro**：你的 Markdown 是资产，HTML 是产物，CSS 你说了算。想加交互（比如一个 demo）时，可以局部引入 React/Vue 岛，不污染全站。

> ⚠️ 你的专业是计算机，不是纯前端。Astro 的学习成本主要在「组件语法」，一天足够。

### 3.3 样式方案：不用 Tailwind

这是个有分歧的点，说清楚理由：

极简黑白灰的全站 CSS **大约 400 行**，其中 150 行是设计变量。用 Tailwind 会带来：

- 每个标签都要记类名（`text-neutral-600` / `leading-relaxed`）；
- 文章正文（Markdown 渲染的裸 HTML）仍然需要单独写一套 prose 样式，Tailwind 的 typography 插件其实是在「补」这件事；
- 构建链多一环。

**但如果你更习惯 Tailwind**，改用它也完全可行，只是我建议第一版先用原生 CSS 把设计系统定下来 —— 变量化的 CSS 在极简风格里是更干净的抽象。

## 4. 设计系统

### 4.1 色彩

极简黑白灰的关键不是「没有颜色」，而是**灰阶要好用**。

| 变量 | 浅色 | 深色 | 用途 |
|---|---|---|---|
| `--bg` | `#fdfdfc` | `#121212` | 页面底色（不用纯白，减轻屏幕疲劳） |
| `--fg` | `#1a1a1a` | `#e8e6e3` | 正文（不用纯黑，避免生硬） |
| `--fg-muted` | `#6b6b6b` | `#9a9a9a` | 次要文字、日期、说明 |
| `--fg-faint` | `#9e9e9e` | `#6a6a6a` | 分隔符、占位 |
| `--line` | `#e5e4e2` | `#2a2a2a` | 分割线、边框 |
| `--accent` | `#1a1a1a` | `#e8e6e3` | 链接（默认与正文同色，靠下划线区分） |

**无强调色**是有意的：黑白灰体系里塞一个蓝色链接会立刻显得廉价。链接用 `text-decoration: underline` + `text-underline-offset: 3px` 区分。

### 4.2 字体

```css
--font-sans: -apple-system, "PingFang SC", "Microsoft YaHei",
             "Noto Sans SC", system-ui, sans-serif;
--font-serif: "Noto Serif SC", "Songti SC", Georgia, serif;
--font-mono: "JetBrains Mono", "Cascadia Code", Consolas, monospace;
```

- **标题用衬线**（`--font-serif`）：中文衬线在小字号下可读性差，但作为 24–40px 的标题非常出彩，能给极简风加一点「出版物质感」。
- **正文用无衬线**：屏幕阅读的中文无衬线更稳。
- 不自托管字体文件（首版），用系统栈 → 零字体下载、无 FOUT。后期若追求一致性，再引入 `Noto Sans SC` 子集化。

### 4.3 尺度

| 项 | 值 |
|---|---|
| 基准字号 | 16px（正文 `1rem`） |
| 正文行高 | `1.75`（中文比英文需要更大行距） |
| 正文最大宽度 | `68ch`（约 34 个汉字/行，舒适阅读） |
| 页面容器宽度 | `1080px` |
| 间距节奏 | 8px 基准：`8 / 16 / 24 / 40 / 64 / 96` |
| 圆角 | `4px`（图片、卡片），代码块 `6px` |
| 标题字阶 | 1.25 倍率：16 → 20 → 25 → 31 → 39 → 49 |

### 4.4 排版细节（决定「精致」 vs 「模板感」的地方）

- 段间距 `1.5em`，但列表、引用块用更小的间距；
- 中英文之间自动加空格（用 CSS 或写作时手动，建议写作时用中文排版规范）；
- 代码块：浅色主题下用暖灰底 `#f6f5f3`，避免刺眼的白；
- 图片：`border-radius: 4px`，居中，图注用 `--fg-muted` 小字；
- 引用块：左侧 2px 竖线，不用大面积底色；
- 表格：仅横线，无竖线、无斑马纹；
- 链接 hover：下划线从 `--line` 过渡到 `--fg`，150ms。

### 4.5 深色模式

跟随系统 + 手动切换（存 `localStorage`，首屏内联脚本消除闪烁）。
深色不是简单反色：深色下正文对比度降一档，图片加 `brightness(0.9)` 缓冲，代码块底色独立定义。

## 5. 内容模型

### 5.1 文章 `src/content/blog/*.md`

```yaml
---
title: Raft 日志复制的三个坑
description: 一句话摘要，用于列表页和 SEO，控制在 80 字内
pubDate: 2026-11-08
updatedDate: 2026-11-10      # 可选
tags: [分布式, 存储]          # 2-4 个，别超过
draft: false                 # true 则不参与构建
---
```

### 5.2 项目 `src/content/projects/*.md`

```yaml
---
title: 分布式键值存储
description: 一句话说明做了什么、解决了什么问题
year: 2026
role: 独立开发 / 课程项目
stack: [Go, Raft, RocksDB]
repo: https://github.com/...
demo: ""                     # 可选
featured: true               # 是否进首页
order: 1                     # 首页排序
---
```

### 5.3 笔记 `src/content/notes/*.md`（第二阶段）

```yaml
---
title: 《数据密集型应用系统设计》第 5 章
type: book                   # book | link | note
source: "ISBN / 原文链接"
date: 2026-11-01
rating: 5                    # 可选，1-5
---
```

**统一原则**：frontmatter 字段由 schema 强制校验，字段名一旦定下就不要轻易改 —— 这是这个站十年后还能构建的保证。

| 阶段 | 内容 | 预估 | 产出 |
|---|---|---|---|
| **M0** 骨架 | 初始化 Astro、目录、Git、Actions | 0.5 天 | 本地 `pnpm dev` 能跑 |
| **M1** 设计系统 + 首页 | tokens.css、Base 布局、首页三段式 | 1.5 天 | 可看的首页 |
| **M2** 博客 | 列表页、详情页、标签、上一页下一页 | 1 天 | 能发第一篇文章 |
| **M3** 项目 | 列表 + 详情 + 首页精选 | 0.5 天 | 项目能展示 |
| **M4** 关于 + 基建 | 关于页、RSS、sitemap、SEO meta、OG 图 | 0.5 天 | 可分享的链接 |
| **M5** 上线 | GitHub Pages 部署、域名、404 | 0.5 天 | ⭐ 有公网地址 |

**关键判断**：M0–M5 加起来约 **4.5 天**，可以拆成两个周末。**先上线，再完善** —— 一个公网地址的激励作用远大于更多功能。

## 7. 部署

### 7.1 仓库命名（影响 URL，先定）

| 方案 | 地址 | 适用 |
|---|---|---|
| A. `username.github.io` | `https://username.github.io` | 有且只有一个个人站，地址最干净 |
| B. `blog` | `https://username.github.io/blog` | 以后还想放别的东西 |

**建议 A**：个人站就该占住根域名。仓库名可以随时改，但不改最好。

### 7.2 部署流程

```
本地 main 分支 push
   └─→ GitHub Actions 触发
         ├─ pnpm install
         ├─ astro build
         └─ 上传 dist/ → GitHub Pages
```

首次配置需在仓库 Settings → Pages → Source 选 **GitHub Actions**。

### 7.3 一个现实问题：国内访问

GitHub Pages 在国内访问**不稳定**（教育网有时较快，家庭宽带时常抽风）。三个应对：

1. **接受它** —— 作为个人站，慢一点不至于没人看；
2. **加 Cloudflare Pages 镜像** —— 同一份代码双部署，国内走 Cloudflare，速度快很多，仍是免费；
3. **自建 VPS** —— 成本高，不推荐现阶段。

**建议**：第一版只做 GitHub Pages，M6 之后再考虑加 Cloudflare 镜像（同一仓库，零改动）。

### 7.4 域名

- 首版用 `username.github.io`，零成本；
- 若以后买域名（约 ¥60/年）：在 `public/` 放 `CNAME` 文件，DNS 加 4 条 A 记录指向 GitHub Pages IP，并在仓库设置里开启 Enforce HTTPS。
- **不需要备案**（国内服务器才需要）。

## 8. 内容策略（比技术更重要）

站点上线后最常见的失败是「三个月没有新内容」。给你的具体建议：

**可写的四类选题**（都从你眼下正在做的事里长出来）：

1. **论文精读**：读一篇，写一篇。你的研究方向本身就有读者。
2. **踩坑记录**：环境配置、依赖冲突、性能调优 —— 这类文章搜得到，是最实际的流量来源。
3. **课程项目复盘**：做了什么、卡在哪、怎么解决、如果重来会怎么做。
4. **工具与方法**：你的编辑器配置、Git 工作流、读文献的方式。

**节奏**：每月 2 篇。宁可写得深，不要写得快。

**项目页的写法**（面试官只看这一页）：
- 第一段说清**问题**和**你的角色**；
- 中间放**架构图**或关键代码片段（不要贴整个仓库）；
- 结尾写**量化结果**：QPS 提升多少、延迟降低多少、支持多少并发；
- 附上仓库链接和 README 关键段落。

## 10. 已排除的方案（供你参考，避免重复讨论）

| 方案 | 排除原因 |
|---|---|
| Next.js / Nuxt | 应用框架做博客，过度工程；默认带 JS 运行时 |
| Hugo | 构建极快，但 Go 模板对前端背景是负资产 |
| Hexo | 生态衰退，主题定制要改源码 |
| Notion / 语雀转静态 | 数据不在自己手里，样式不可控 |
| WordPress | 需要服务器和数据库，与「静态 + 免费」冲突 |
| 纯手写 HTML | 10 篇文章后就会放弃 |
